# Bug log

One row per problem. Only things that were actually seen go in the first table; anything
that is a worry from reading the code, or was seen once and could not be made to happen
again, goes under **Suspected**. Full write-ups are in [issue-drafts/](issue-drafts/), in
the same shape as the GitHub template (`.github/ISSUE_TEMPLATE/bug_report.md`). Drafts are
local: nothing here has been published as a GitHub issue.

**Severity** — S1 Critical: wrong pairings, results or standings, lost or changed data, or
the app cannot be used. S2 Major: a feature fails or a rule is broken, saved data is
correct. S3 Minor: works but is confusing or awkward. S4 Cosmetic.

**Status** — New → Reproduced → Fixed (retested) / Open / Won't fix / Cannot reproduce.

## Suspected — not reproduced

These come from reading the code on 2026-10-09. None has been seen to go wrong and none has
a failing test. Move one to the table above only after reproducing it.

| SUS-001 | When every possible round contains a rematch, the pairing does not look for the round with the fewest rematches, and the bye is chosen before pairing, so a different bye might have avoided one. | Not tested. The fix for BUG-001 deliberately left this case as it was. | Decide whether it matters at club size; if so, write a test with the smallest example first. |

Whether it is a bug or just a label depends on the intended rule. | Confirm the intended rule; rename the column or change the figure. |

## Usability changes from the 0.2.4 manual test (not defects)

The app did what it was built to do in each of these; they change how it is used.

| Change | What it was | What it is now |
|---|---|---|
| Pod results on the card | Winner on the card, then a window for second place, draws and changes | Winner +5 beside each player; then 2nd +2.5 beside the others and No clear second, all on the card. A draw is entered on the card. Only the saved pod is redrawn: the page keeps its place and the keyboard focus moves to the next choice |
| Saved, provisional and final in words | Colour and a short label | Each card says No result yet, 2nd place still to choose (points provisional), saved and provisional until the round is finalized, or final. A refused save says "Not saved:" and why, and keeps what was entered |
| Corrections need a reason | A reason only for finalized rounds and the confirmed final | Changing or clearing a saved pod result, taking back a recorded knockout and correcting the final all need a non-blank reason, checked in the core and kept in the history with the values before and after. Finishing a pending second place is not a correction and needs none (history: SECOND_PLACE_RECORDED) |
| The top-four final on its page | A window per elimination and a window for the result with a choice per player | Tick players and Record knockout (players ticked together go out together), a short knockout history, one winner choice or No winner, the places as they would be, and one Confirm final results. Placement rules behind How placements work |
| Correcting the final | One choice per player in a long window | The same editor with the saved places above, the places after below, and the reason beside Save; a refused save keeps the window open |
| Draw policy wording | "Eliminated players lose"; "survivors share the draw" | "Knocked-out players lose" with one sentence: players still in draw, knocked-out players lose. Each drawing player gets the full draw points; nothing is split. The default for new events is unchanged; existing events keep theirs |
| Use recommended | Set the rounds to the suggestion, with an "Organizer override" warning | "Use suggested rounds"; the suggestion and the number of checked-in players it is for are shown beside the rounds, and none is shown below three players |
| The final's controls (second manual test) | A list of players with tick boxes, Record knockout, round choices for the ending and Confirm final results in the page footer | Two sections side by side, stacked in a narrow window. Record knockout: a pill per player still in, several can be selected, and Confirm knockout, disabled until the selection is valid. Determine winner: a pill per player still in, one at a time, No winner / Draw as its own choice, the places and Confirm final results. The selection is cleared only after a save; a refused or failed save keeps it and says why beside the control, with a log reference when the database refused the write |
